# 金字塔原理方法论（Pyramid Principles）

提炼长篇内容时，对原文做一次"金字塔化"重构。本文件提供方法论依据与分类准则。

## 一、金字塔结构的三个基本规则

1. **纵向关系（以上统下）**：金字塔每一层的观点，必须是对其下层观点的**概括**；下层观点必须是上层观点的**论据/支撑**。不允许"上层说 A，下层却讲 B"。
2. **横向关系（归类分组）**：同一层级内的各组观点之间必须**互斥且穷尽**（MECE），且必须按某种**逻辑顺序**排列（时间 / 结构 / 程度）。
3. **结论先行**：表达顺序永远是**先结论、后论据**。读者/听众应最先听到最重要的判断，而非背景铺垫。

## 二、结论先行（中心论点）

- 每份材料只提炼**一个中心论点**（如果原文确实包含多个并列议题，拆成多个金字塔，各自结论先行）。
- 中心论点应是一句**完整、可判断对错**的话，而不是标题或话题。例：
  - 错误：材料讲的是"某项目预算"。
  - 正确：某项目预算严重超支且无追加来源，需立即暂停二期投入。

## 三、归类分组（MECE 归纳）

同一层级的要点必须满足：
- **Mutually Exclusive（互斥）**：各项之间不重叠、不重复。
- **Collectively Exhaustive（穷尽）**：各项合起来覆盖该层级的全部内容。

常用归类框架（按材料类型选用）：
- **时间顺序**：过去 → 现在 → 未来；事前 → 事中 → 事后。
- **结构顺序**：按组成要素拆分（如人 / 财 / 物 / 事；市场 / 产品 / 渠道 / 服务）。
- **程度顺序**：按重要性、优先级、严重度、规模从高到低排列。
- **因果顺序**：原因 → 结果；问题 → 影响 → 对策。

每组数量控制：**3~7 组为宜**。超过 7 组说明归类过细，需继续合并；少于 3 组通常说明归类过粗，需拆分。

## 四、逻辑递进（同一层级的排列）

同一层级的分论点按以下任一逻辑推进：
- **时间递进**：按发生先后。
- **结构递进**：按组成部分的从属关系。
- **程度递进**：按重要 / 紧急 / 影响由大到小（汇报场景尤其适用，把最重要、最想让对方记住的放最前）。

## 五、MECE 快速自检清单

提炼每组要点后，逐项问：
1. 这组里有没有两项说的是同一件事？（有 → 违反互斥，需合并或区分）
2. 这组是否覆盖了该议题的全部重要侧面？（缺 → 违反穷尽，需补齐）
3. 我漏掉了原文里的反方观点 / 风险 / 反对意见吗？（汇报材料尤其容易只留支持性证据，需主动补反证）
4. 每一条都能向上归到某条上层论点、向下能找到原文论据吗？

## 六、两种模式的取舍准则

- **模式A（个人精读）**：MECE 分组做到最细，允许保留例外、反例、细节、存疑点，追求信息完整度与可追溯。
- **模式B（汇报）**：MECE 分组做到"够决策用即可"，只保留能支撑中心论点的分论点与证据，把最要紧的放最前；反证与风险以"风险提示"形式附在最末，不打断主结论链。
